## 1. 九个核心问题

### Q1. 研究对象与范围如何界定？

- **对象**：开源自托管 RAG 平台层框架（3.0-4.0 代际），提供"摄取→索引检索→问答/Agent"完整闭环
- **候选池**（文献综述初筛）：五强 WeKnora/RAGFlow/Dify/FastGPT/MaxKB + 观察席 QAnything/AnythingLLM；
  闭源 SaaS（Coze 私有化等）仅作对照
- **范本**：WeKnora（深潜对象，也是候选之一）
- **排除**：纯向量数据库、LLM 网关、纯 SaaS、个人向工具（Khoj/Open WebUI 不作企业候选）

### Q2. 评估指标体系如何建立？

采用**范本验证法**（三步，系统性思维落地）：

```
Step1 维度归纳：WeKnora 深潜解构 → 素质清单候选维度
Step2 理论补全：与 RAGAS 分层评估共识、企业场景约束（文献综述 §1.2/§1.3）交叉 → 补漏修正
Step3 泛化检验：清单在全部候选上全覆盖检验 → 不可评估的维度降级或标注
```

指标体系框架（7 维，详见 M2 产出）：

| 维度 | 来源 | 关键子项 |
|------|------|---------|
| D1 摄取能力 | 范本深潜 | 文档解析/OCR/版面分析/数据源连接/增量更新 |
| D2 检索质量 | RAGAS 共识 | 混合检索/GraphRAG/rerank；Context Precision/Recall 工程指标 |
| D3 生成与Agent | 范本+共识 | 忠实性/答案相关性；Agent 推理/MCP/工作流编排 |
| D4 企业级特性（硬门槛） | 文献 G2 | 多租户/RBAC/审计/加密/OIDC/IM 集成 |
| D5 可观测与运维 | 范本+共识 | tracing（Langfuse 类）/任务监控/索引治理（新鲜度/血缘）/部署形态 |
| D6 开放与生态 | 范本+共识 | API 完备度/MCP/协议开放（MIT 类）/社区活跃度 |
| D7 成本与资源 | 选型指南 | 部署门槛/资源消耗/TCO/维护投入 |

### Q3. 数据如何收集？

- **证据分级制**（先例验证）：①源码/官方文档实证 ②官方声称 ③社区广泛共识 ④推断；
  关键结论须至少两个独立来源，或显式标注单一来源级别
- **来源**：GitHub 仓库（README/代码/issues/releases）、官方文档站、2026 年评测报告、社区讨论
- **版本锚定**（文献 G3）：每条结论标注所依据的框架版本号与日期

### Q4. 如何评估打分？

- 每维度 1-5 分制，附证据级标注；D4 企业级特性为**硬门槛**——不达标者不进 top3，无论其他维度多高
- 权重设计（初步，M3 交叉印证时校准）：
  - 企业场景基准权重：D2 检索质量 25%、D1 摄取 20%、D4 企业特性 20%（门槛性质）、D3 生成与Agent 15%、D5 运维 10%、D6 生态 5%、D7 成本 5%
- **场景分型打分**（H3）：同一打分按三个场景画像重算——复杂文档型（D1 权重↑）/应用编排型（D3↑）/开箱问答型（D7+D2↑）
- **禁止**按功能清单数量计分（功能对比陷阱，文献 §3.2）

### Q5. 研究问题如何细化？

|--------|-----------|------|

| SQ1b 素质清单如何泛化为 7 维指标体系 | 指标构建 | 评估指标体系 |
| SQ2a 候选框架全景与最新版本现状 | 候选盘点 | 候选盘点报告 |

| SQ3b top3 各自的长处与短处 | 审查员复核 | 长短处分析（报告章节） |

### Q6. 假设如何验证？

| 假设 | 验证方法 | 判定标准 |
|------|---------|---------|
| H1 基础 RAG 趋同，差异在摄取/企业特性/Agent | 候选功能矩阵对照 | 矩阵中"基础 RAG"列全部达标即为支持 |
| H2 范本清单可泛化 | 7 维全覆盖检验 | 候选池无不可评估维度（或已显式降级） |
| H3 top3 按场景分型 | 场景加权重算 | 三个场景画像产生不同 top 排序即为支持 |
| H4 开源主流 | 候选盘点+SaaS 对照 | 企业级候选开源自托管占比 ≥80% |

### Q8. 风险与局限？

| 风险 | 等级 | 应对 |
|------|------|------|
| 无实机部署测试，结论依赖公开证据 | 中 | 证据分级制+版本锚定+报告显式声明局限；给出"可复现验证要点"供用户实测 |
| 周更节奏致结论快速过时 | 中 | 时点锚定 2026-09；报告注明评估版本 |
| 打分主观性 | 中 | 双 Agent 独立打分+审查员仲裁（互相印证模式） |
| 中文评测来源质量参差 | 低 | 优先一级证据；③级证据须多来源一致 |
| GitHub MCP 不可用（本会话 401） | 低 | 回退 WebFetch/WebSearch 获取仓库信息 |

### Q9. 成果形式与验收标准？

- **最终交付**：06-final-deliverables/知识库框架选型研究报告.md（含：指标体系+候选盘点+top3 分型推荐+长短处分析+可复现验证要点）
- **验收标准**：SQ1-SQ3 全部有结论且证据分级；top3 推荐附打分表与场景说明；长短处分析每条附证据来源；假设 H1-H4 全部给出 支持/证伪/存疑 判定

## 2. Agent 团队配置（阶段 5 产出）

### 2.1 生成依据（三优先级推演）

1. **课题关键词推导**：知识库框架、RAG、企业级、WeKnora 范本、评估指标、top3 选型
   → 初版：知识库调研 Agent、评估指标 Agent、协调员
2. **文献综述细化**：企业特性是分水岭（G2）→ 范本深潜 Agent 专设企业特性审计；候选池锁定 5+2（§3.1）→ 候选盘点 Agent 范围明确；版本锚定要求（G3）→ 全部调研 Agent 通用约束
3. **方法论流程分解**：系统性思维（指标构建）→ 指标构建 Agent；DSR（打分→推荐→验证）→ 审查员承担交叉印证

### 2.2 团队构成（5 人）

| Agent | 角色 | 任务 | 协作模式 |
|-------|------|------|---------|
| coordinator 研究协调员 | 主研究员 | 任务分解、调度、假设检验、打分综合、报告撰写 | 独立+印证+冲突 |
| agent-weknora-deepdive 范本深潜Agent | 领域专家 | SQ1a：WeKnora 架构/摄取流水线/检索管线/Agent 引擎/Wiki 模式/企业特性（多租户 RBAC 审计加密 OIDC）逐一解构，产出素质清单 | 独立为主，与指标构建互相印证 |
| agent-landscape 候选盘点Agent | 领域专家 | SQ2a/SQ2b：候选池 5+2 框架的最新版本、功能矩阵、企业特性达标情况、社区生态盘点 | 独立为主，与范本深潜互相印证 |
| agent-metrics 指标构建Agent | 方法论专家 | SQ1b：范本素质清单+RAGAS 分层共识+企业约束 → 7 维指标体系（含量化指标与验证方法、权重设计） | 独立+印证（理论标尺） |
| agent-reviewer 跨学科审查员 | 辅助 | 交叉印证：范本深潜 vs 候选盘点 vs 指标体系三方一致性；双打分仲裁；证据分级抽查；分歧记录 | 印证+冲突 |

### 2.3 团队协作拓扑

```
M2 并行调研期：┌─ 范本深潜Agent ─┐
               ├─ 候选盘点Agent ─┤→ 产出三份调研报告（独立研究模式）
               └─ 指标构建Agent ─┘
M3 交叉印证期：三方报告 → 审查员（互相印证模式）→ 分歧记录至 05-collaboration-logs
M4 综合交付期：协调员打分综合 → top3 分型推荐 → 审查员终审 → 最终报告
```

## 4. 质量标准（沿用 config.yaml 研究质量标准）

1. 所有研究结论必须有证据支撑（证据分级制：①源码/官方文档实证 ②官方声称 ③社区广泛共识 ④推断）
2. 所有引用必须有明确出处（URL+访问日期+所依据版本）
3. 研究方法必须可复现（评分表/权重/证据公开）
4. 所有假设必须给出 支持/证伪/存疑 结论
5. 推断结论不得表述为事实（标注证据级别）
