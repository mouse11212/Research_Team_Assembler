- **主轨 = 宽松轨**（课题定义："多租户/RBAC/审计/私有化/IM或API" 5 项至少 4 项 ✅）：达标 2 席——WeKnora 5/5（全项①级）、RAGFlow 4/5（审计为唯一短板，标注"可外部补偿（审计网关/ELK）+ 生产风险警告"）；临界 AnythingLLM 3/5；Dify CE / FastGPT OSS / QAnything 2/5；MaxKB 1-2/5 存疑。
- **辅助轨 = 严格轨**（指标体系三否决项：私有化部署/RBAC/审计日志，任一 ❌ 不达标）仅作**风险提示**：仅 WeKnora 3/3 通过。若单采严格轨，top3 将塌缩至 1 席——违背用户"top3"意图，且审计可通过外部系统补偿，故不采为主轨（交叉印证记录移交建议 #1/#12 的塌缩预案由本双轨裁决化解）。

**总分排序（7 框架）**：WeKnora 4.30 ＞ RAGFlow 3.85 ＞ Dify 2.85 ＞ FastGPT 2.35 ＞ MaxKB 2.30 ＝ AnythingLLM 2.30 ＞ QAnything 1.80。

**一句话决策建议（④）**：企业级且要求治理开箱全内置 → WeKnora；复杂版面/扫描件文档为核心、可接受审计外部补偿 → RAGFlow；以工作流/Agent 应用编排为核心、接受商业授权 → Dify。

### 2.5 打分规则要点（§4 打分的执行依据）

1. 通用五档锚点：5=行业标杆（①+③双证）· 4=优秀（①级实证完整、无已知明显短板）· 3=够用（①/②级达及格线、有已知小缺陷）· 2=不足（仅②③级声称或③级已知缺陷）· 1=缺失（③级多来源确认缺失）。
2. 证据模式→分数上限（无实机测试适用）：①级机制证据+③级第三方实测数值达标=5；①级机制证据无实测=4（标注"未实测"）；仅②级声称=3；仅③级共识=2。
3. 防漂移硬规则：5 分必须①+③双证；4 分必须①级证据；**③④级证据不得支撑 4 分及以上**；禁止功能数量计分。
4. 各维 5/3/1 分速查锚点按指标体系 §5.3（D1 以"DeepDoc 级版面分析+③级共识最强"为 5 分锚；D4 以"否决 3 项+条件 3 项全具①级"为 5 分锚等）。
5. 打分数据全部来自三方报告，无新调研；报告未检索到的项给"N/A（未评估）"并说明（§4.6）。

### 5.2 复杂文档型（金融合同/法律文书/技术手册，D1=30）

- **第一梯队**：WeKnora 4.25 / RAGFlow 4.00（差距 0.25）。
- **使用前提**：
  - 选 **RAGFlow**：主文档为扫描件/双栏/表格密集，审计缺口可用外部系统（审计网关/ELK）补偿并接受生产合规风险警告；资源预算 ≥16GB/50G；RBAC 深度（角色级 ACL）使用前自验证（存疑 #9）。
  - 选 **WeKnora**：要求治理开箱全内置（审计/RBAC/多租户①级）且文档以规整+结构化为主；复杂版面解析期望不高于 DeepDoc 级时可接受；接受 2-4 周迭代节奏与升级回归测试负担。

### 5.3 应用编排型（工作流+Agent 应用，D3=30）

- **榜单**：WeKnora 4.25 / RAGFlow 3.80 / **Dify 3.05（编排单项断层领先）**。
- **使用前提**：
  - 核心诉求是可视化工作流编排+Agent 应用 → **Dify 为业界事实主流（③）**，但必须接受其一：**商业授权（企业版 5/5 企业特性齐全）**，或 CE 单租户无审计/RBAC/SSO 限制并自行补足；不得以 CE 源码运营多租户 SaaS（许可证限制 ①）。
  - WeKnora 为 Agent 原生（ReAct+技能沙箱+MCP Server）但**无可视化编排**——适合"治理优先于编排"、以 Agent 而非画布工作流为主的组织（④）；若同时要重编排，需叠加 Dify/FastGPT 或等待其演进（盘点分型交叉提示）。
  - RAGFlow v0.27 Agentic RAG 追赶明显，编排生态仍不及 Dify。

### 5.4 开箱问答型（小团队快速上线，D7=25）

- **榜单**：WeKnora 4.20 / RAGFlow 3.70 / Dify 3.05；**备选**：FastGPT（裁决4）、MaxKB（条件性，裁决3）、AnythingLLM（裁决5）。
- **使用前提**：
  - 选 WeKnora：Minimal 2C/4G ① 可起；接受多容器 Compose（PG+Redis+docreader）与版本追随成本。
  - 选 FastGPT：仅当"开箱口碑+中文社区"权重极高且**接受商业版 Pro 授权补齐团队权限/SSO/审计**（裁决4）。
  - 选 MaxKB：单容器最低门槛+双 LTS 线具真实优势（①），但多租户/RBAC/审计的 X-Pack 边界矛盾——**须先取得官方商务书面确认**方可按企业用途采信（裁决3）。
  - 选 AnythingLLM：海外语境轻量场景；需前置统一身份层（SIMPLE_SSO 透传需 Authentik 类代理 ①）补 SSO；接受无租户层级与审计不含问答内容。

### 5.5 趋势展望（范本特有、未泛化入指标的能力，④/①）

WeKnora v0.8.0 所体现的 Agent 平台化方向——技能市场/技能即资产（ClawHub/SkillHub/git/zip 安装，①）、跨会话长期记忆（五类记忆+pending 确认，①）、AI Wiki 知识自维护（①）、无状态 Agent 引擎（③）——是"知识库→知识工作平台"演进的前沿信号，当前候选池独有或少量具备，本课题不将其纳入打分（避免全员低分），建议选型后持续跟踪。

## 6. top3 长处与短处

### 6.1 WeKnora v0.8.0（总分 4.30）

**长处**：
1. 企业治理候选池唯一全项①级（①）：多租户（Tenant+组织+10GB 配额源码默认值）/RBAC 四级角色+API Key 能力域+KB 白名单/双层审计（工作空间级+平台级）/OIDC JWKS/AES-256-GCM 凭证落盘加密+密钥轮换——唯一双轨全过（宽松 5/5+严格 3/3）。
2. 检索管线工程深度（①）：加权 RRF（0.7/0.3 默认值源码实证）、rerank 六环节（复合打分 0.6/0.3/0.1+MMR λ=0.7+FAQ/Wiki 加权）、GraphRAG（Neo4j 每 KB 可配抽取规则）、查询理解（9 类意图+失败兜底）、10 种检索引擎可插拔。
3. Agent 平台化（①）：官方 PyPI MCP Server（源码实测 33 工具/README 29 滞后）、工具沙箱三后端（Docker/E2B/Cube，非 root+出网白名单+限额）、Human-in-the-loop 审批（②）、AI Wiki 知识自维护（修订历史/diff/一键回滚）、跨会话长期记忆。
4. 摄取治理（①）：13 格式/24 解析器、anydoc 进程内+MinerU 外挂分层、三层自适应+父子分块、分块编辑/快照/diff/回滚/自动重索引、Asynq 五队列+DLQ（支撑 4 万文档级 Wiki 摄取）。
5. MIT 协议+快速迭代（①）：11 版/4.5 月，SECURITY.md/QA.md/ROADMAP 齐备。

**短处**：
1. 复杂 PDF 版面解析非标杆（③④）：内置 pdf_parser+可选 MinerU 的模式与 RAGFlow DeepDoc 定位不同；未检索到官方复杂 PDF 解析基准。
2. 英文社区薄弱（③）：2026 社区对比表中英文社区评"几乎为零"，教程生态未出中文圈；选型对比中"想要更大英文社区"是他人弃选理由之一。
3. 安全披露集中（①漏洞库）：2026 年披露 7 个 CVE（含 2 个 CVSS 9.9，均集中于 0.2.x-0.3.x 时代、已全部修复）——反映早期 MCP 面与多租户面攻击面设计缺陷；生产部署必须最新版+关公开注册+出口流量过滤。
4. 中文 BM25 跨引擎一致性未验证（①+④）：gojieba 仅用于评测分词，BM25 关键词检索由向量库引擎实现（pgvector 走 PG 全文检索+ParadeDB），跨引擎中文效果需自测。
5. 无可视化工作流编排（未检索到，Agent 为主）。
6. 双周级迭代的升级成本（④）：每版含 migration 文件，v0.8.0 含 Breaking Change（本地沙箱后端移除、Docker 沙箱默认关闭，①）。

**适用场景**：复杂文档+企业治理双强需求；治理优先于编排的组织；需要知识库能力外借（MCP）的 AI 开发团队。
**使用前提**：接受快速迭代升级节奏与回归测试负担；生产执行安全加固（最新版/关公开注册/出口过滤）；对英文社区依赖不敏感。

## 8. 可复现验证要点（用户实测建议）

> 本课题未实机部署（研究设计 Q8），以下为最终落地前的实测清单。全部阈值来源：RAGAS 分层评估共识与 2026 生产监控共识（③，±0.05 浮动已在指标体系声明）。

### 8.1 真实文档对照测试方法

1. **构建企业 golden dataset 并纳入版本控制**：选取 50-200 条企业真实问题，标注标准答案与 ground-truth 引用 chunk；**必须含中文语料**（WeKnora 中文 BM25 跨引擎一致性为其已知短板——gojieba 仅用于评测分词、关键词检索由向量库引擎实现①；中文 golden dataset 是交叉印证移交建议 #10 的必补项）。
2. **文档形态覆盖**：按企业实际配比纳入扫描件/双栏 PDF/复杂表格（测 RAGFlow DeepDoc vs WeKnora docreader+MinerU 的实际差距）、规整 Office 文档（测基线）、历史归档文档（测增量与新鲜度）。
3. **跨框架同题对照**：同一 golden dataset 在 2-3 个候选框架上用**同一 LLM/Embedding** 跑同题（隔离变量），对比答案正确性与引用可定位性；引用颗粒度要求段落/chunk 级（D3.4 企业合规底线）。
4. **权限强制实测**（交叉印证移交建议 #10，分歧 #9 存疑项的落地验证）：在 RAGFlow 与 AnythingLLM 上构造"无权账号提问无权文档"用例，确认检索/问答链路强制执行权限（非仅 UI 隐藏）；RAGFlow 另测**审计导出**（问答记录+管理操作是否可查询/导出）。

### 8.2 RAGAS 指标自测方法

1. **必测四项**：Faithfulness（≥0.85 推荐、<0.7 不上线）、Context Precision（≥0.70 及格、rerank 实测可提至 0.85+③）、Context Recall（≥0.75 推荐）、Answer Relevancy（≥0.80）；复杂文档型场景加测 Context Entity Recall（≥0.75 参考）与 Noise Sensitivity（≤0.3 为优，衡量抗无关 chunk 干扰）。
2. **防虚高规则**：评判模型必须≠生成模型；Faithfulness 须与 Context Precision 配对使用（1.0 仅保证未超出上下文编造）；Answer Correctness 只作补充参考、不作独立门禁。
3. **上线门禁接入 CI/CD**：faithfulness 或 context_precision 任一 <0.7 阻断上线。
4. **生产监控四项告警阈值**（③，PremAI 2026）：幻觉率 >5%、P95 检索延迟 >500ms、上下文利用率 <40%、负反馈 >10%。

### 8.3 CVE 与版本注意
