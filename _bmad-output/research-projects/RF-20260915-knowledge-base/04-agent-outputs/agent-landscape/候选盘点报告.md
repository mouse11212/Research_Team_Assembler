### 1.2 方法与局限

- **检索手段**：GitHub MCP 本会话 401 不可用（研究设计 Q8 已备案）；GitHub REST API 匿名请求被出口 IP 限流（403）。全部数据经 WebFetch 抓取 GitHub 仓库页/releases 页/raw 文档 + WebSearch 检索官方文档站、官方发布博客与 DeepWiki 代码分析页获得。
- **日期注记**：GitHub releases 页面部分条目仅显示"月日"不显示年份；本报告版本日期均以页面相对时间（"released this"）与项目活跃上下文交叉确认，个别无年份处已按上下文推断为 2026 年并在表中注明。
- **未实机部署测试**：结论全部依赖公开证据（研究设计 Q8 已备案），"可复现验证要点"由最终报告提供。
- **WeKnora 深潜分工**：WeKnora 的架构级细节由范本深潜Agent（SQ1a）负责，本报告仅卡片级+矩阵行，未做逐文件源码验证（证据来自仓库内官方文档与 DeepWiki 代码分析，级别 ①）。
- **FastGPT / MaxKB / Dify 的版本边界**：三者均存在"开源版 vs 商业版（X-Pack）"功能分界线，矩阵与达标表均按**开源社区版口径**打分，商业版能力单独注明（否则会落入"功能对比陷阱"——把付费能力算进免费版本）。

### 3.1 矩阵要点观察

1. **基础 RAG 已趋同**（支持 H1）：7 个框架在"向量检索+RAG 问答+多模型接入"上全部达标；差异集中在摄取深度、GraphRAG、MCP、企业特性与协议上。
2. **摄取与 GraphRAG 分水岭**：RAGFlow（8 类解析器+20+ 连接器）与 WeKnora（25+ 格式+Neo4j GraphRAG）显著领先；Dify/FastGPT/MaxKB 对复杂文档依赖外部解析。
3. **MCP 已成 2025-2026 标配**：除休眠的 QAnything 外全部实现（RAGFlow v0.20.0 / Dify v1.6.0 / FastGPT v4.9.6 / MaxKB v2.1.0 / AnythingLLM v1.8.0 均有官方版本锚点）；WeKnora 更以官方 PyPI MCP Server 包向外暴露。
4. **"功能对比陷阱"重灾区**：Dify/FastGPT/MaxKB 三家的多租户、RBAC、SSO、审计、IM 发布、API 开放度中，大量能力只在商业版/X-Pack——按开源版口径打分后，三者企业特性显著缩水（详见 §4）。

### 4.1 达标结论摘要

- **开源免费版全面达标者仅 2 席**：WeKnora（5/5，唯一全项①级证据）与 RAGFlow（4/5，审计短板）。
- **Dify / FastGPT / MaxKB 呈现"开源做功能、企业特性收钱"的商业模式**：三者开源版均不达标，达标能力锁在 EE/商业版/X-Pack 中——选型时必须按"免费开源版"口径评估，或接受商业授权成本。
- **AnythingLLM 为临界黑马**：MIT 协议+3 项 ✅，若团队已有统一身份层（前置代理），可低成本补齐 SSO 后接近达标；但多租户与审计仍弱于 WeKnora/RAGFlow。
- **QAnything 双杀出局**：企业特性缺失 + 项目休眠，仅作文档解析技术参考。
- 该结果与假设 H4（企业级候选开源自托管占比 ≥80%）方向一致：7 席中 2 席免费开源版直接达标、1 席临界、3 席需商业付费补全、1 席出局。

## 6. 定位分型观察（供 top3 分型参考）

按研究设计 H3 的三场景画像，给出各框架倾向（④推断级别，供协调员综合打分时参考）：

**复杂文档型（D1 摄取权重↑）**
- 第一梯队：RAGFlow（DeepDoc+8 类解析器+20+ 连接器，唯一弱点是资源消耗）；WeKnora（docreader 25+ 格式+Neo4j GraphRAG+Wiki 模式，摄取到图谱的闭环完整）。
- Dify/FastGPT/MaxKB 规整文档够用，烂文档场景差距拉大（③评测共识）；AnythingLLM/QAnything 各有特色但前者无 OCR、后者已休眠。

**应用编排型（D3 生成与 Agent 权重↑）**
- 断层领先：Dify（可视化工作流+Agent+MCP 双向+插件市场）。
- 中文生态强替补：FastGPT（编排+商业版补齐企业特性，但开源版无团队权限是硬伤）；RAGFlow（v0.20 起 Agent+Workflow 统一，v0.27 Agentic RAG 追赶明显，但编排生态仍不及 Dify）。
- WeKnora 为 Agent 原生（ReAct+Skill 沙箱），但无可视化编排，适合"治理优先于编排"的组织。

**开箱问答型（D7 成本+D2 检索权重↑）**
- MaxKB（单容器+最低门槛+双 LTS 线，但企业特性依赖 X-Pack）；FastGPT（开箱问答口碑+最快发布节奏，但团队权限为商业版）；AnythingLLM（MIT+桌面 App+最低合规成本，海外语境）。

**分型交叉提示**：
- WeKnora 是唯一"复杂文档+企业治理"双强的 MIT 选项，但其工作流编排缺位——若企业同时要重编排，需叠加 Dify/FastGPT 或等待其演进。
- RAGFlow 是唯一 Apache-2.0 且摄取+企业特性（审计除外）基本自洽的选项，适合"以框架为底座做二次开发"的路线。
- Dify/FastGPT 的企业特性达标依赖付费版本，选型时成本模型需按"开源版+商业授权"而非"开源免费"计算。
