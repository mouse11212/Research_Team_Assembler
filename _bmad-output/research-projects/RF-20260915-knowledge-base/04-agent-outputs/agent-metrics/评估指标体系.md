## 1. 设计依据

### 1.1 范本验证法中的定位

本课题采用范本验证法三步：**范本归纳（WeKnora 深潜）→ 理论补全（本文件）→ 泛化检验（M3 交叉印证）**。
本文件按「理论补全」路径先行构建：以 RAGAS 分层评估共识 + 企业场景约束为理论标尺展开 7 维框架，
为范本深潜 Agent 正在并行产出的素质清单预留合并接口（每维「范本校准点」）。
M3 由审查员将两者合并校准：素质清单中本体系未覆盖的项 → 增补指标；本体系中无法在候选上评估的项 → 降级或标注。

### 1.3 指标设计四原则

1. **可操作性**：每个指标须能量化，或能按 ①② 级证据明确判 ✅/❌；禁止"功能完善""体验良好"类表述。
2. **证据分级**：每项打分须标注证据级别——①源码/官方文档实证 ②官方声称 ③社区广泛共识 ④推断；③④级不得表述为事实。
3. **深度非数量**：禁止功能数量计分（功能对比陷阱）；衡量"实现深度与质量"，如 IM 集成计"企业主流 IM 是否覆盖"而非"接入几个 IM"。
4. **范本可校准**：每维标注「范本校准点」，为 M3 素质清单合并留接口。

### 1.4 证据级别与来源标记约定

- 证据级别：①源码/官方文档实证 ②官方声称 ③社区广泛共识 ④本设计推断
- 来源标记：`[RAGAS]` RAGAS 官方文档 ｜ `[共识26]` 2026 评测共识（多来源一致）｜ `[CT26]` Context Trustworthiness 2026 共识（Atlan 等）｜ `[企业]` 企业场景约束（文献综述 §1.3）｜ `[范本]` WeKnora 范本深潜（待 M3 合并）｜ `[设计]` 本设计推断

### 1.5 无实机测试下的度量双模式

本课题不实机部署候选框架（研究设计 §Q8 局限），因此工程指标（D2/D3 中的 RAGAS 类）采用双模式度量：

- **实证模式（理想）**：实机部署 + golden dataset + RAGAS 评测——写入最终报告「可复现验证要点」供用户实测；
- **证据模式（本研究默认）**：以 ①② 级证据判定"影响该指标的能力/机制存在性"（如 rerank 可配置之于 Context Precision），
  并引用 ③ 级第三方实测数值作锚点。规则：无实测数据但有 ①级机制证据 → 上限 4 分并标注"未实测"；仅 ②级声称 → 上限 3 分。

## 2. 七维指标体系

> 指标总表见附录 A。每维结构：维度定位 → 指标表 → 范本校准点。

### D1 摄取能力（输入质量决定上限——"垃圾进垃圾出"）

**维度定位**：文档解析/OCR/版面分析/数据源连接/增量更新。企业知识库的文档形态复杂（扫描件、双栏 PDF、复杂表格），摄取深度是 2026 年框架间差异最大的维度之一（文献共识 H1）。

| 编号 | 指标 | 定义 | 度量方法 | 阈值/锚点 | 来源（证据级） |
|------|------|------|---------|-----------|--------------|
| D1.1 | 文档格式覆盖与解析深度 | 对 PDF/Word/PPT/Excel/Markdown 等主流格式的解析能力，及解析引擎是否为文档场景针对性设计（自有引擎 vs 通用库套壳） | ✅/❌ 判定（①级证据）：五类主流格式全覆盖，且 ①级证据（源码/文档）确认解析引擎有针对性设计（格式特化处理逻辑） | 五类主流格式全覆盖为企业及格线 | [设计]④ + [范本] |
| D1.2 | 复杂版面与扫描件处理（OCR+版面分析） | 扫描件 OCR 识别、版面分析（双栏/图文混排）、表格还原保真度 | ✅/❌ 判定（①级证据）：存在专用版面分析/OCR 模块；深度锚点引用 ③级第三方对比实测结论 | 复杂文档型场景必须 ✅；③级锚点：RAGFlow DeepDoc 为 2026 共识复杂版面标杆 | [共识26]③ |
| D1.3 | 分块策略完备性 | 分块方式（固定/递归/语义/父子分块 Parent-Child）的可配置性与实现深度 | ✅/❌ 判定（①级证据）：至少支持父子分块或语义分块之一，且分块参数可配置 | 父子/语义分块至少其一（③级共识：固定分块是企业 RAG 常见翻车点） | [范本] + [共识26]③ |
| D1.4 | 数据源连接与增量同步 | 连接企业数据源（企微文档/飞书/Confluence/语雀/Notion/GitLab 等）的能力；增量更新机制（定时轮询/事件触发/CDC） | 两项独立 ✅/❌ 判定（①②级证据）：(a) 企业主流数据源覆盖 ≥2 类（按企业常见度判定深度，非连接器总数）；(b) 增量更新机制存在 | (a)(b) 企业场景均须 ✅；增量延迟 ≤1h 为 3 分锚，事件/CDC 驱动为 5 分锚 | [企业] + [范本] + [设计]④ |
| D1.5 | 摄取管线可靠性 | 异步任务队列、失败重试、断点续传、批量导入等工程可靠性机制 | ✅/❌ 判定（①级证据）：异步队列 + 失败重试均存在 | 企业批量迁移场景必须 ✅（无重试的摄取管线在大批量导入时不可用） | [范本] + [设计]④ |

**范本校准点 D1**：深潜 Agent 的 WeKnora 摄取流水线解构（DocReader 解析器细节/父子分块实现/Asynq 队列/数据源同步机制）用于：(1) 校准 D1.1/D1.2「深度」判定的证据示例；(2) 若素质清单含本文未覆盖的摄取素质（如文档类型自动路由、重复文档去重），增补指标或并入 D1.1；(3) 校准 D1.4 增量机制形式锚点（定时 vs 事件驱动）。

### D2 检索质量（RAGAS 分层共识的检索层）

**维度定位**：混合检索/GraphRAG/rerank 能力 + 检索层工程指标。检索错、切片错、Prompt 错要能定位到组件（分层评估共识）。本维是权重最高维度。

| 编号 | 指标 | 定义 | 度量方法 | 阈值/锚点 | 来源（证据级） |
|------|------|------|---------|-----------|--------------|
| D2.1 | 混合检索能力 | 多路召回（BM25 关键词 + 稠密向量）与融合（RRF 等）；加分项：GraphRAG/知识图谱召回 | ✅/❌ 判定（①级证据确认检索管线实现）：双路召回+融合 = 及格；+GraphRAG 召回 = 加分（非及格线）；+检索权重可配置/向量库多后端 = 再加分 | 双路召回+融合为 2026 基准（单一向量检索在企业文档场景 precision 不足） | [范本] + [共识26]③ |
| D2.2 | Context Precision（上下文精准率） | RAGAS：检索到的 chunk 中真正相关者占比（检索噪声控制） | 实证：RAGAS evaluate（golden dataset，评判模型须≠生成模型）；证据模式：①级证据判定"影响 precision 的机制"（rerank 可配置/过滤规则/metadata 过滤）+ 引用 ③级实测数值 | ≥0.70 及格；上线门禁 <0.7 不上线；rerank 实测可提至 0.85+（③级共识：性价比最高优化） | [RAGAS]① + [共识26]③ |
| D2.3 | Context Recall（上下文召回率） | RAGAS：标准答案所需证据被检索到的比例（漏检控制）；唯一强制要求标注 reference 的核心指标 | 实证：RAGAS（需 ground-truth reference）；证据模式：①级证据判定多路召回/查询改写机制 | ≥0.75 推荐（③级多源区间 0.70-0.75） | [RAGAS]① + [共识26]③ |
| D2.4 | Context Entity Recall（上下文实体召回率） | RAGAS 扩展：标准答案中实体（日期/编号/专名）在检索上下文中的出现比例；金融/法律/医药等事实密集型领域关键 | 实证：RAGAS ContextEntityRecall（需 reference）；证据模式：①级证据判定实体敏感检索机制（实体感知分块/命名实体索引） | 复杂文档型场景必测项；参考锚 ≥0.75（与 Context Recall 同档） | [RAGAS]① + [共识26]③ + [设计]④ |
| D2.5 | Noise Sensitivity（噪声敏感度） | RAGAS 扩展：注入无关 chunk 后答案错误率上升程度；衡量检索鲁棒性，越低越好 | 实证：RAGAS NoiseSensitivity（注入干扰 chunk 测 score 下降）；证据模式：①级证据判定 rerank + 忽略无关上下文约束机制 | ≤0.3 为优（分级：0-0.1 卓越/0.1-0.3 良好/0.3-0.5 中等/0.5-1.0 差） | [RAGAS]① + [共识26]③ |
| D2.6 | 检索延迟与 rerank 配置 | 检索链路 P95 延迟；rerank 模型接入/开关的可配置性 | 实证：P95 检索延迟实测；证据模式：①级证据确认 rerank 可配置（模型可选/开关）✅/❌ | P95 ≤500ms（生产监控告警线）；rerank 可配置为 2026 企业必选 | [共识26]③ |

**范本校准点 D2**：深潜的检索管线解构（BM25+稠密+GraphRAG 三路召回/errgroup 并行/RRF 融合）用于：(1) 校准 D2.1 加分项「GraphRAG 召回」是否保留独立加分——若候选盘点显示仅范本具备，保留加分但显式注明"非及格线"；(2) rerank 在范本中的实现形态 → 校准 D2.6 判定证据路径；(3) 若范本素质清单含"查询重写/意图识别"素质 → 增补 D2.7。

### D3 生成与Agent（RAGAS 分层共识的生成层 + 4.0 代能力）

**维度定位**：忠实性/答案相关性/引用溯源 + Agent 推理/MCP/工作流编排。衡量"机器用知识办事"的深度，是 4.0 代际框架与 3.0 代际的分水岭。

| 编号 | 指标 | 定义 | 度量方法 | 阈值/锚点 | 来源（证据级） |
|------|------|------|---------|-----------|--------------|
| D3.1 | Faithfulness（忠实性） | RAGAS：答案中可被检索上下文证实的声明占比（幻觉控制）；注意 1.0 仅保证未超出上下文编造，须与 Context Precision 配对使用 | 实证：RAGAS（评判模型≠生成模型）；生产监控：幻觉率滚动监控 | ≥0.85 推荐（③级多源 0.80-0.85）；<0.7 不上线（门禁）；合规场景可收紧至 0.95（regulated 团队实践）；生产幻觉率 >5% 告警 | [RAGAS]① + [共识26]③ |
| D3.2 | Answer Relevancy（答案相关性） | RAGAS：回答直接切题程度（惩罚兜圈/堆砌/离题） | 实证：RAGAS；生产监控：采样评分告警 | ≥0.80 推荐；生产监控 <0.70 告警 | [RAGAS]① + [共识26]③ |
| D3.3 | Answer Correctness（答案正确性） | RAGAS 扩展：结合语义相似度与事实正确性的综合正确性 | 实证：RAGAS AnswerCorrectness（需 reference） | 无统一共识阈值；作为 Faithfulness+Relevancy 的补充参考，不作独立门禁 | [RAGAS]① + [共识26]③ |
| D3.4 | 引用溯源能力 | 答案附引用且可定位到源文档 chunk/页码；企业合规"答案有据可查"的底线 | ✅/❌ 判定（①②级证据）：引用可跳转原文 chunk；加分：引用颗粒度（段落级 > 文档级） | 企业场景必须 ✅（无引用的 RAG 在合规审计场景不可采信） | [企业] + [范本] + [设计]④ |
| D3.5 | Agent 推理深度 | 多步推理闭环（ReAct 类）、工具调用（内置+MCP）、并行工具调用、human-in-the-loop 审批；衡量"机器用知识办事"深度而非工具数量 | 各机制独立 ✅/❌ 判定（①级证据）：多步推理 / 工具调用 / 人工审批 三项 | 应用编排型场景：多步推理+工具调用必选；人工审批为金融/敏感场景加分项 | [范本] + [共识26]③ |
| D3.6 | 工作流编排能力 | 可视化/DSL 编排多步骤应用（检索→生成→工具→条件分支→循环） | ✅/❌ 判定（①级证据）：编排界面/DSL 存在 + 节点类型覆盖（条件分支/循环/并行） | 应用编排型场景必须 ✅；纯问答场景非必选 | [共识26]③ + [设计]④ |
| D3.7 | MCP 集成能力 | 作为 MCP 客户端接入外部工具 + 作为 MCP Server 对外提供知识库工具 | ✅/❌ 判定（①级证据）：client/server 双向；深度：server 工具覆盖知识库核心操作（检索/列表/管理，即读写闭环而非仅检索） | 应用编排型场景 client ✅ 必选；server 为生态加分项 | [范本] + [共识26]③ |

**范本校准点 D3**：深潜 Agent 引擎解构（ReAct/并行工具/human-in-the-loop/MCP 工具清单）用于：(1) 校准 D3.5「深」的 5 分锚点具体形态；(2) 范本 Wiki 模式（知识自维护：源文档变化自动更新+版本回滚）若为独立素质 → 增补 D3.8「知识自维护」或并入 D5.2/D5.3 索引治理——此为本文预留的最大合并位；(3) 校准 D3.4 引用颗粒度在范本的实现。

### D4 企业级特性（硬门槛维度）

**维度定位**：多租户/RBAC/审计/加密/OIDC/IM 集成。企业特性是"企业级"与"个人玩具"的分水岭（文献空白 G2）。本维兼有**门槛（否决）**与**计分**双重角色：门槛规则见 §3，本节为计分指标表。

| 编号 | 指标 | 门槛角色 | 定义 | 度量方法 | 来源（证据级） |
|------|------|---------|------|---------|--------------|
| D4.1 | 私有化部署（数据主权） | **一票否决** | 可完全离线/内网自托管部署，核心链路（摄取/检索/生成）不依赖外部 SaaS | ①级证据：官方自托管部署指南（Docker/K8s）+ 核心链路本地闭环判定 | [企业] + 课题定义① |
| D4.2 | 权限治理（RBAC） | **一票否决** | 文档/知识库级（或更细）可见性权限控制，且在检索/问答链路强制执行（非仅 UI 层隐藏） | ①级证据：权限模型实现 + 检索链路鉴权；深度：权限粒度（租户/角色/文档级） | [企业] + [范本] |
| D4.3 | 审计日志 | **一票否决** | 记录"谁在何时问什么/改什么"（问答记录+管理操作记录），可查询/导出 | ①级证据：审计日志实现与导出能力 | [企业] |
| D4.4 | 多租户隔离 | 条件项 | 租户间数据/索引/模型配置隔离 | ①级证据：租户概念在数据层实现（非仅 UI 分组） | [范本] + 课题定义 |
| D4.5 | 加密与身份认证 | 条件项 | API 密钥静态加密、传输 TLS、OIDC/SSO 企业身份接入 | ✅/❌ 判定（①级证据）：密钥静态加密 ✅ + OIDC/SSO ✅ 为满；仅 TLS 为部分 | [范本] + [企业] |
| D4.6 | IM/API 系统集成 | 条件项 | 接入企业 IM（企微/飞书/Slack 等）或可经 API 被内部系统调用 | ✅/❌ 判定（①②级证据）：IM 接入或完整 REST API 至少其一；计"企业主流 IM（企微/飞书）覆盖"✅ 而非 IM 总数 | [企业] |
| D4.7 | 安全漏洞响应 | 计分项 | 已知 CVE 状况与修复响应时效（安全公告渠道/依赖更新节奏） | ①级证据：安全公告渠道存在性 + CVE 清单（GitHub Security/OSV）+ 修复时效；锚点：未修复 Critical CVE 且 >30 天无官方响应 → 本项 ≤2 并在报告加安全警示；无 Critical CVE 且有安全公告 → 4-5 | [共识26]③ + [设计]④ |

**范本校准点 D4**：深潜的企业特性审计（多租户/RBAC 四级权限/审计/加密 AES-256-GCM/OIDC 实现细节）用于：(1) 校准否决项判定标准的证据示例（何谓"检索链路强制执行权限"）；(2) 校准 D4.7——范本已知 CVE（③级：约 10 个含 2 Critical）的 ①级核实与修复状态确认；(3) 若范本发现本文未列的企业素质（如数据导出合规、数据驻留策略）→ 增补条件项。

### D5 可观测与运维（治理反馈闭环）

**维度定位**：tracing/任务监控/索引治理（新鲜度/血缘）/部署形态。对应 2026 第五维度 Context Trustworthiness（索引内容新鲜度/血缘/与规范来源一致性）——企业知识库区别于个人工具的关键分水岭（文献 §1.2）。

> 生产监控共识阈值（③级，PremAI 2026）：幻觉率 >5% 告警、P95 检索延迟 >500ms 告警、上下文利用率 <40% 告警、负反馈 >10% 告警。作为本维"监控能力判定"的锚点。

| 编号 | 指标 | 定义 | 度量方法 | 阈值/锚点 | 来源（证据级） |
|------|------|------|---------|-----------|--------------|
| D5.1 | Tracing 与链路可观测 | 检索/生成链路追踪（Langfuse/OpenTelemetry 类集成），支持定位到组件（检索错/切片错/Prompt 错） | ✅/❌ 判定（①级证据）：tracing 集成存在；深度：每跳（查询改写/召回/rerank/生成）可观测 + 指标面板覆盖上述监控阈值 | 企业场景必须 ✅（分层评估要能定位组件、生产要能监控） | [范本] + [共识26]③ |
| D5.2 | 索引治理—新鲜度 | CT26 第一子维：索引内容新鲜度治理——增量更新延迟、stale retrieval rate（过期内容被检索率）、覆盖漂移（flagged/total） | ①级证据：增量更新机制（接 D1.4）+ 过期内容标记/下架机制；实证：stale retrieval rate 滚动窗口监控 | 增量更新延迟 ≤1h 为 3 分锚；stale retrieval rate 趋势监控（CT26：未经治理的内容实测 52% 编造率 vs 治理内容近零） | [CT26]① + [设计]④ |
| D5.3 | 索引治理—血缘（lineage） | CT26 第二子维：chunk → 源文档 → 版本的可追溯链；引用可回溯至规范来源（canonical source）；源文档变化自动触发重索引 | ✅/❌ 判定（①级证据）：chunk 级溯源（引用跳转+源文档版本记录）；加分：事件驱动重索引（优于定时轮询） | 企业合规场景必须 ✅（无法追溯的答案在审计中不可采信）；CT26 实证：元数据治理使 precision 从 73.3% 提至 82.5% | [CT26]① + [范本] |
| D5.4 | 任务监控与重试 | 摄取/索引任务队列的监控仪表盘、失败任务手动/自动重试 | ✅/❌ 判定（①级证据）：任务状态可查 + 失败重试机制 | 企业批量导入场景必须 ✅ | [范本] + [设计]④ |
| D5.5 | 部署形态与升级路径 | 部署形态（Docker Compose / K8s Helm / 存储后端可选）+ 版本升级/数据迁移能力 | 两项独立 ✅/❌ 判定（①级证据）：(a) 双形态（Compose+K8s）或单形态+清晰文档；(b) 升级迁移指南/数据兼容声明 | 周更节奏框架必须有 (b)（升级路径缺失则运维成本不可控） | [范本] + [设计]④ |

**范本校准点 D5**：深潜的 Langfuse 集成深度/任务队列仪表盘/Wiki 源文档变化自动更新机制用于：(1) 校准 D5.1「每跳可观测」锚点；(2) 校准 D5.3 血缘实现形态（自动更新 vs 手动重建）；(3) 若范本有"索引版本管理/一键回滚"素质（Wiki 版本历史）→ 增补 D5.6 或并入 D5.3。

## 3. D4 硬门槛规则

### 3.1 门槛双级结构

| 层级 | 项 | 规则 |
|------|-----|------|
| 一票否决项（3 项） | D4.1 私有化部署 / D4.2 权限治理（RBAC）/ D4.3 审计日志 | **任一 ❌ → 不进 top3**，不论总分多高 |
| 条件项（3 项） | D4.4 多租户隔离 / D4.5 加密与身份认证 / D4.6 IM/API 集成 | **至少 1 项 ✅** |
| 门槛公式 | 否决 3 项全过 **且** 条件项 ≥1 | 与课题定义"支持企业使用 = 多租户/RBAC/审计/私有化/IM或API集成 至少 4 项"对齐（3 否决 ⊂ 原 5 项，+1 条件 = ≥4 项） |

### 3.2 判定标准（证据要求）

1. **否决项判定必须基于 ①级证据**（源码/官方文档实证实现机制）；仅 ②级官方声称 → 降级标注"存疑"，不算通过；
   ③级证据须多来源一致方可采信。
2. **否决项判定要点**：
   - D4.1：官方有自托管部署指南（Docker/K8s），且核心链路（摄取/检索/生成）本地闭环，不依赖外部 SaaS 服务；闭源"私有化定制版"需付费即 ❌。
   - D4.2：权限在**检索/问答链路强制执行**（检索时过滤无权文档），而非仅 UI 层隐藏；粒度至少文档/知识库级。
   - D4.3：审计日志覆盖**问答记录**（谁在何时问什么）+ **管理操作**（谁在何时改什么），且可查询/导出。
3. **场景不变性**：门槛不随场景画像放宽——本课题对象即"企业级"知识库，个人向工具（AnythingLLM 类）在开箱问答型场景也不豁免。
4. **安全特殊条款**：D4.7 不进门槛（开源框架普遍存在 CVE，作否决会全灭）。但若 ①级证据确认存在未修复 Critical CVE 且官方 >30 天无响应 → 审查员可裁定该候选 D4 维度总分 ≤2 并在最终报告加"安全警示"；是否仍进 top3 由 M3 仲裁并记录分歧。
5. **通过门槛后的计分**：D4 维度分（1-5）仅在通过门槛的候选间比较；未过门槛者直接排除，不再计 D4 分。

## 4. 权重设计

### 4.1 基准权重（企业场景，7 维合计 100%）

| 维度 | 权重 | 理由 |
|------|------|------|
| D2 检索质量 | 25% | 知识库核心价值所在；分层评估共识的工程重点 |
| D1 摄取能力 | 20% | 输入质量决定上限；2026 框架间差异最大维度（H1） |
| D4 企业级特性 | 20% | 门槛性质（§3）+ 通过门槛后的深度计分 |
| D3 生成与Agent | 15% | 4.0 代能力；基础 RAG 已趋同（H1） |
| D5 可观测与运维 | 10% | 索引治理是 2026 第五维度，持续运维保障 |
| D6 开放与生态 | 5% | 集成与可持续性 |
| D7 成本与资源 | 5% | 落地可行性 |

### 4.2 三场景画像权重变体

| 维度 | 基准 | 复杂文档型（金融/法律/技术文档，D1↑） | 应用编排型（工作流+Agent 应用，D3↑） | 开箱问答型（小团队快速上线，D7+D2↑） |
|------|------|------|------|------|
| D1 摄取 | 20 | **30** | 10 | 15 |
| D2 检索 | 25 | 25 | 20 | **30** |
| D3 生成与Agent | 15 | 10 | **30** | 5 |
| D4 企业特性 | 20 | 20 | 20 | 15 |
| D5 可观测运维 | 10 | 5 | 5 | 5 |
| D6 开放生态 | 5 | 5 | **10** | 5 |
| D7 成本资源 | 5 | 5 | 5 | **25** |
| 合计 | 100 | 100 | 100 | 100 |

**变体理由**：
- **复杂文档型**：D1 权重升至 30——扫描件/表格/双栏版面解析深度是金融法律技术文档场景的核心瓶颈（③级共识：RAGFlow DeepDoc 即以此立身）；D3 降至 10（纯问答为主，Agent 非刚需）。
- **应用编排型**：D3 升至 30 + D6 升至 10——工作流编排/MCP/API 生态是编排底座的命脉（③级共识：Dify 以编排立身）；D1 降至 10（文档形态较规整）。
- **开箱问答型**：D7 升至 25 + D2 升至 30——小团队无专职研发，部署门槛与维护投入是一票否决级现实约束（③级共识：FastGPT 2核2G 起、MaxKB 低门槛即以此立身）；D3 降至 5（基础问答够用）。

**两条固定规则**：
1. D4 硬门槛（§3）在三个场景画像中**均不变**——否决项不随画像放宽。
2. 各画像中 D4 权重仅影响"通过门槛候选"的分值构成，不影响门槛本身。

### 4.3 场景画像判定规则（谁用哪个权重）

按以下三问判定（④推断，供协调员在 M4 为用户画像定位时使用）：
1. 主文档是否复杂版面/扫描件/表格密集（金融合同、法律文书、技术手册）？是 → 复杂文档型。
2. 是否要构建多步骤工作流/Agent 应用（审批流、多系统联动），而非纯问答？是 → 应用编排型。
3. 是否小团队（≤10 人、无专职研发）且目标是快速上线稳定问答？是 → 开箱问答型。
若多选命中，按"最痛点优先"取最高权重画像重算一次，报告给出主画像结论。

## 5. 评分细则（1-5 分锚点）

### 5.1 通用五档锚点

| 分 | 档名 | 锚点描述 | 证据要求 |
|----|------|---------|---------|
| 5 | 行业标杆 | 该维度核心指标深度领先：①级证据确认实现，且 ③级多来源公认候选池内最强/业界标杆（如 RAGFlow DeepDoc 之于复杂版面解析）；量化指标实测达推荐阈值+余量 | ① + ③ 双证 |
| 4 | 优秀 | 完整实现且 ①级证据确认，无已知明显短板，满足企业场景全部硬需求；量化指标实测达推荐阈值 | ① |
| 3 | 够用 | 核心能力达及格线，①或②级证据；有已知小缺陷或深度一般；量化指标达门禁线（未达推荐线） | ①/② |
| 2 | 不足 | 仅部分实现，或仅②③级声称（无 ①级实证），或有 ③级已知明显缺陷（不影响核心但拖累使用） | ②/③ |
| 1 | 缺失 | 无此能力；或 ③级多来源确认缺失；或仅 roadmap 声称 | ③/④ |

**防漂移硬规则**：
- 5 分必须 ①+③ 双证；4 分必须 ①级证据；**③④级证据不得支撑 4 分及以上**。
- 禁止功能数量计分：API 端点总数、IM 接入个数、工具数量、格式数量均不得直接作为加分依据；只计"覆盖企业关键需求与否"与"实现深度"。

### 5.2 证据模式→分数转换（无实测工程指标适用）

| 证据情形 | 分数上限 |
|---------|---------|
| ①级机制证据 + ③级第三方实测数值达标 | 5 |
| ①级机制证据，无实测数值 | 4（标注"未实测"） |
| 仅②级官方声称 | 3 |
| 仅③级社区共识（有/无）且无①②级 | 2 |

### 5.3 各维 5/3/1 分锚点速查

| 维度 | 5 分（标杆） | 3 分（够用） | 1 分（缺失） |
|------|-------------|-------------|-------------|
| D1 | 专用版面分析+OCR 引擎且 ③级共识候选池最强（DeepDoc 级）+ 事件驱动增量同步 | 主流格式解析 + 扫描 OCR 可用，复杂版面一般；定时增量同步 | 仅基础文本抽取，无 OCR/无增量同步 |
| D2 | 三路召回+RRF+rerank 可配，③级实测 CP≥0.85 | 双路召回+RRF+rerank 可配 | 仅单路向量检索，无 rerank |

| D6 | 四域 API+双向 MCP+MIT+高活跃社区 ①级全证 | 四域 API+MIT 协议 | 无 API 或协议受限 |

## 6. 打分流程（双打分 + 仲裁）

> 依据研究设计 §Q8 风险应对「双 Agent 独立打分 + 审查员仲裁」展开。执行于 M4，记录于 05-collaboration-logs/交叉印证记录.md。

| 步骤 | 动作 | 执行者 | 规则 |
|------|------|--------|------|
| S1 证据预审 | 抽查各候选打分将引用的证据级别与版本锚定 | 审查员 | ①②级证据占比 ≥70% 视为健康；③④级须显式标注；版本须注明框架版本号+2026-09 时点 |
| S2 独立打分 | 按本体系 7 维 38 项指标逐项打分（互不参考） | 协调员 + 候选盘点 Agent | 每人独立完成完整打分表；每项附证据级别与出处 |
| S3 一致性检验 | 对比双打分表 | 审查员 | 分歧 ≤1 分：讨论取共识或均值（记录过程）；分歧 >1 分：进入 S4 仲裁 |

## 7. 使用注意

1. **版本锚定**：所有打分结论必须注明所依据的框架版本号与评估日期（2026-09 时点）；候选框架周更节奏下，2026-09 之后的版本变化须重新核证。
2. **证据级别红线**：③④级证据不得表述为事实；关键结论须至少两个独立来源或显式标注单一来源级别（研究设计质量标准）。
3. **无实机测试局限**：本课题不实机部署（研究设计 §Q8），D2/D3 工程指标按 §1.5 证据模式打分；最终报告须附「可复现验证要点」供用户实测，包括：golden dataset 纳入版本控制、上线门禁接入 CI/CD（faithfulness 与 context_precision 任一 <0.7 阻断）、评判模型须与生成模型不同（防分数虚高）、生产监控四项阈值（幻觉率 >5%、P95 检索延迟 >500ms、上下文利用率 <40%、负反馈 >10% 告警）。
4. **阈值来源差异声明**：RAGAS 推荐阈值在 2026 各来源间有 ±0.05 浮动（如 faithfulness 0.80-0.85、context_precision 0.70-0.75）；本体系采用研究设计给定共识值为默认（faithfulness>0.85 / answer_relevancy>0.80 / context_precision>0.70 / context_recall>0.75），打分时允许在该区间内引用来源说明；门禁线（<0.7 不上线）各来源一致。
5. **禁止功能数量计分**：见 §5.1 硬规则；审查员在 S1/S4 复核时逐项检查。
6. **指标维护**：本文件为 v1.0（理论补全路径先行版）；M3 与范本素质清单合并校准后升 v1.1，校准操作按各维「范本校准点」执行——素质清单新增项 → 增补指标；本体系不可评估项 → 降级或标注。
7. **门槛与权重的先后次序**：D4 硬门槛过滤（S5）先于场景加权（S6）；任何场景画像下否决项均不可豁免。
