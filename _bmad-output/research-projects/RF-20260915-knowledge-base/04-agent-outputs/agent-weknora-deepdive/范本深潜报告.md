## 2. 架构还原

### 2.1 三体分层架构（①）

- **Go 业务后端**（`internal/`）：核心业务编排、RAG 管线、Agent 引擎、多租户/RBAC、异步任务（Asynq v0.26，`go.mod`）。v0.6.0 升级 Go 1.26.0（CHANGELOG）。
- **Python DocReader 解析服务**（`docreader/`）：独立 gRPC 服务（默认端口 50051，`DOCREADER_GRPC_MAX_WORKERS` 默认 4），负责文档解析/OCR/多模态。与应用间以 **gRPC TLS + Token** 认证（README）。
- **Vue 3 + Vite 前端**（`frontend/`）：Web UI，TypeScript 类型检查（`npm run type-check`）。
- 服务拓扑：app + docreader + PostgreSQL（pgvector 默认）+ Redis（Asynq 队列）+ 对象存储（本地/MinIO/S3 等）+ 可选 Neo4j（图谱）+ 可选 Langfuse（追踪）。

### 2.2 模块化可替换设计（①）

- 官方文档语："Fully modular pipeline from document parsing, vectorization, and retrieval to LLM inference"、"every component is swappable and extensible"（README）。
- 检索引擎工厂模式：`internal/application/repository/retriever/` 下 10 个引擎目录——**doris、elasticsearch、milvus、neo4j、opensearch、postgres、qdrant、sqlite、tencentvectordb、weaviate**（源码目录实证，含 Neo4j 图库与 SQLite 本地轻量后端）。
- 摄取管线插件化：chat_pipeline 下 `query_understand.go / search.go / rerank.go / merge.go / merge_overlap.go / into_chat_message.go / chat_completion_stream.go` 插件链（官网文档 + DeepWiki 代码路径）。

### 2.3 部署形态（①）

- Docker Compose 为主（profiles：默认核心服务 / `full` 全功能 / `neo4j` 图谱 / `minio` 对象存储 / `langfuse` 追踪，可组合 `--profile`）。
- K8s Helm：仓库根有 `helm/` 目录（源码实证）。
- Lite 单二进制：`deploy/weknora-lite.service`（systemd 服务文件，源码实证）。
- 私有化/离线部署、数据主权（README ②）。
- 官方镜像：`wechatopenai/weknora-docreader` 等（docreader README）。

## 3. 子系统解构

### 3.1 摄取流水线

**解析格式覆盖（①）**：README 列出 13 种格式（PDF/Word/Txt/Markdown/HTML/EPUB/MHTML/Images/CSV/Excel/PPT/JSON/XMind）；docreader/parser/ 目录实证解析器：pdf、docx（含 docx2/docx_merge）、epub、excel（含 xlsx_repair/xlsx_merge）、html、image、markdown、**markitdown**（微软 MarkItDown）、mhtml、**opendataloader**、web、xmind、ppt（ppt_convert/pptx_media）、chain_parser（多解析器串联）。

**解析引擎分层（①）**：
- 内置 Python parser 组；
- **anydoc 引擎**：v0.8.0 引入"in-process anydoc Office 解析器"，Office 文件在 Go 进程内经 `third_party/anydoc-go` 解析，免 docreader 往返（CHANGELOG + 源码目录 `third_party/anydoc-go` 实证）；
- **MinerU**：可选高级解析服务（`MINERU_ENDPOINT` 环境变量，docreader README），用于复杂文档结构识别；
- v0.6.1 加入 OpenDataLoader + PaddleOCR-VL 解析器；OCR 与多模态（VLM 图片描述 / ASR，README）。

**分块策略（①）**：
- 自适应三层分块（v0.5.2 起，带实时预览）：Tier1 按 Markdown 标题层级 / Tier2 启发式（编号章节、分页符）/ Tier3 递归字符兜底（官网文档 + DeepWiki）；
- **父子分块 Parent-Child**（v0.3.3 引入）：先分父块再切子块，检索命中小块、拼接父块补全上下文（`SplitParentChild`；官网文档 `resolveParentChunks`）；
- 分块手工编辑 + 版本快照 + diff + 一键回滚 + 自动重索引（README；v0.7.2）。

**数据源连接器（①）**：源码 `internal/datasource/connector/` 实证 7 个——**feishu、gitlab、ima（腾讯 IMA）、notion、rss、yuque、dingtalk**；支持增量与全量同步；飞书 docx 走 blocks API 逐类型下钻（v0.7.2）；GitLab 项目同步为知识源（v0.8.0，#2656）。

**摄取入口（③→①）**：文件上传（安全校验 + 哈希去重）、URL 抓取、手工录入、Passage 直转、FAQ 批量导入（`CreateKnowledgeFromFile/FromURL/FromManual/processDocumentFromPassage/UpsertFAQEntries`，DeepWiki 代码路径）；v0.8.0 增加文件夹拖拽上传保留结构、文档下载动作。

**异步任务架构（①）**：Asynq 队列，五个专用队列 `core / enrichment / summary / graph / multimodal`（`internal/types/task.go`）+ 分阶段 worker pool（core/post-process/enrichment/maintenance + 共享弹性池，v0.7.0）；DLQ 兜底（v0.5.2，支撑 4 万文档级 KB 的 Wiki 摄取）；三类型富化任务：向量索引、图谱抽取（`TypeChunkExtract`）、数据表摘要（`TypeDataTableSummary`，xlsx/csv）。

### 3.2 检索管线

**多路召回（①）**：六种可组合检索策略（README）：BM25 稀疏 / Dense 稠密 / GraphRAG / 父子分块 / HNSW 加速 pgvector（1024 维）/ 多维索引（按章节、标签、时间 + 权限隔离）。FAQ 库走 FAQ 向量索引（无关键词索引），文档库走向量 + 关键词双索引（官网文档）。

**加权 RRF 融合（①）**：官网文档原文——混合模式 `score = vectorWeight/(k+vectorRank) + keywordWeight/(k+keywordRank)`，"对分数尺度免疫"；`internal/types/retrieval_config.go` 源码实证：`RRFK` 平滑常数、`RRFVectorWeight` 默认 0.7 / `RRFKeywordWeight` 默认 0.3，均可按租户配置；纯单路时按 chunk 保留最高分去重。

**向量库支持（①）**：README 列 8 种（pgvector/Elasticsearch/OpenSearch/Milvus/Weaviate/Qdrant/Apache Doris/Tencent VectorDB）+ 源码多出 neo4j（图）与 sqlite（本地）。v0.6.0 起 KB 检索可跨多个向量库扇出（fan-out）；v0.6.3 知识库检索扇出联邦查询。pgvector 为默认（百万级场景），十亿级建议 Milvus/Weaviate/Qdrant（③ 53ai 文章）。v0.6.2 pgvector 默认开启 HNSW（针对 1024 维 bge-m3 调优），官方称"百万级向量查询毫秒级返回"（②③）。

**rerank 管线（①）**：官网文档实证六环节——Passage 清洗（剥离 Markdown 语法、保留代码/公式块）/ Passage 增强（拼入图片 Caption/OCR 与生成问题）/ 阈值过滤（top1 兜底 + 阈值降级重试 `threshold*0.7` 下限 0.3 + API 失败回退原始结果）/ **复合打分 `0.6*模型分+0.3*检索基础分+0.1*来源权重`**（web 来源权重 0.95）/ FAQ 加权（`FAQScoreBoost>1.0`）/ **MMR 多样性选择**（λ=0.7，`mmr=0.7*relevance-0.3*max_jaccard_redundancy`）；Wiki 页面后置加权 `wikiBoostFactor=1.3`。Rerank 提供方：火山引擎（批量请求）、腾讯 LKEAP、Zhipu（v0.7.1）。

**查询理解（①）**：PluginQueryUnderstand 单插件做改写 + 意图分类（9 类意图枚举：kb_search/web_search/greeting/chitchat/follow_up/image_only/doc_only/summarize/clarification），模型输出 JSON，解析失败时原文 + 默认 kb_search 兜底；可指定独立小模型 `QueryUnderstandModelID`；查询扩展不调用 LLM、本地启发式生成变体（去停用词/词序调整/关键短语），召回不足时触发。

**上下文合并（①）**：PluginMerge 八步管线——输入选择（优先 RerankResult）/ ID+内容签名去重 / 历史引用注入（Jaccard 过滤、最多 3 条）/ 父子块解析（image_ocr/image_caption 子块用当前 parent_text 补齐）/ 按 KnowledgeID+ChunkType 分组顺序拼接（相邻/包含合并取最高分）/ FAQ 答案填充 / 短文本邻居扩展（<350 字符拉邻居至 850）/ 跨库近重复删除（归一化包含判断/token 重合率≥0.85 删低分者）。

**中文分词（①）**：gojieba v1.4.7 依赖实证（go.mod），用于内置评测模块分词（`internal/types/evaluation.go:9-21`）；查询扩展侧中文分词走 jieba CutForSearch 避免逐字 token（③ DeepWiki 聚合）；BM25 关键词索引由向量库引擎实现（pgvector 场景 = PG 全文检索 + ParadeDB BM25 打分，`paradedb.score(id)` 实证）。

**GraphRAG（①）**：Neo4j 后端（`NEO4J_ENABLE=true`），摄取后异步抽取实体/关系（`TypeChunkExtract` 入 QueueGraph），每 KB 可独立配置抽取规则（实体类型/属性/关系标签）；检索时 `QueryKnowledgeGraphTool` 与 chunk 搜索并行，按 `NameSpace{KnowledgeBase, Knowledge}` 在 Neo4j 中 SearchNode，结果并入上下文支持多跳推理。

### 3.3 生成与 Agent

**ReAct Agent 引擎（③→①）**：think→analyze→act→observe 循环，引擎刻意无状态——每轮从 DB 重载会话历史（`LoadAgentHistory`），简化多租户多实例状态一致性；每轮恰好发射一次 `EventAgentComplete`，推理树形展示（DeepWiki，代码路径 `internal/agent/engine.go`）。

**MCP 集成（①）**：
- 官方 MCP Server 发布 PyPI（`tencent-weknora-mcp`），README 声称 29 个工具，源码 `mcp-server/weknora_mcp_server.py` 实测 **33 个 `@mcp.tool()` 装饰器**（v0.8.0 快照，存在 README 滞后）；三种传输 stdio/SSE/HTTP（`run_stdio/run_sse/run_http`）；
- 客户端侧：MCP 工具多传输接入、OAuth2（v0.6.3 MCP OAuth2 for services、v0.7.0 对话中 OAuth）、`@Skill/@MCP` 提及按轮限定运行时作用域（v0.7.0）；
- **Human-in-the-loop 工具审批**（v0.5.2，②）。

**技能沙箱（①）**：`internal/sandbox/` 目录实证三后端——docker（Docker Engine API）、e2b（e2b_remote_client，E2B 协议 + 自托管支持）、cube（cube_remote_client，远端控制面）；会话级持久化沙箱（同会话内 shell_exec/文件/附件/产物共享，会话结束回收）；容器内**非 Root 执行（uid 1000）**、出网默认阻断 + 域名白名单、CPU/内存限额与 TTL 按租户配置；v0.8.0 破环变更：本地主机进程沙箱后端移除、Docker 后端默认关闭需显式开启；沙箱操作发射产品级 Langfuse span（v0.8.0）。另含 desktop 沙箱（RFB/终端桥接）与沙箱快照（snapshot）。

**技能目录（①②）**：工作空间技能目录 + 租户级技能市场，安装源 ClawHub/SkillHub/git/zip；按需加载（先暴露名称简介，匹配后 `read_skill` 读详情省 token）；版本快照、流式日志、实时中止；管理员控制各 Agent 技能可见性。

**跨会话长记忆（①）**：v0.8.0 引入（migration `000084_memory`），与 v0.7.1 移除的 Neo4j 会话记忆独立；五类记忆 profile/preference/fact/task/interest；推断项默认 pending 需用户确认；兴趣参与文档亲和度加权（Document Affinity），在向量检索阶段给反复引用文献更高个性化权重；`search_memory` 工具；记忆 API 仅限全权限 API Key。

**AI Wiki 模式（①②）**：v0.5.0 GA；Agent 把文档蒸馏为结构化、互链 Markdown Wiki 页面 + 知识图谱（浏览器可视化）；浏览器内手工编辑；v0.7.2 页面修订历史/行级 diff/一键回滚（覆盖前保留每个版本）；任务队列 + DLQ 支撑 4 万文档级 KB；独立 Wiki 摄取池；Wiki 页面检索时加权 1.3（①）。

**其他 Agent 能力（②③）**：Data Analyst Agent（对 CSV/Excel 执行 SQL）；自定义 Agent（v0.3.0）；Web 搜索自主决策（12 家引擎：DuckDuckGo 默认/Bing/Google/Tavily/Baidu/Ollama/SearXNG/Keenable/Zhipu/Exa/Metaso，v0.8.0 新增 Metaso、Exa）；多模态（VLM/ASR）。

**模型提供商（①）**：20+ LLM 集成——OpenAI/Azure OpenAI/Anthropic/DeepSeek/Qwen/Zhipu/Hunyuan/Doubao/Gemini/MiniMax/NVIDIA/Novita AI/SiliconFlow/OpenRouter/Requesty/LiteLLM/Ollama；Embedding：Ollama/BGE/GTE/Zhipu/OpenAI 兼容；LLM/Embedding/Rerank/VLM/ASR 五类模型分类管理。

### 3.4 企业特性

- **多租户（①）**：Tenant 工作空间模型，`internal/types/tenant.go:99-100` 源码实证**默认存储配额 10GB**（gorm default 10737418240，含向量/原文件/文本/索引）；v0.7.1 后支持免租户（tenantless）部署与门控自助开通工作空间；Organization 跨租户知识库共享（③）。
- **RBAC（①②）**：工作空间四级角色矩阵 Owner/Admin/Contributor/Viewer（v0.6.0），每 KB 归属权限，跨工作空间超级管理员，邀请制工作空间。
- **审计日志（①②）**：每工作空间审计日志 + v0.7.1 平台级活动审计（作用域审计跟踪）；v0.7.2 起合并 Wiki 操作日志入 KB Activity 单一历史面（移除独立 wiki log）。
- **凭证安全（①）**：`internal/utils/crypto.go` 实证 **AES-256-GCM 落盘加密**（API Key、MCP/数据源凭证），支持平滑密钥轮换；gRPC TLS + Token（app↔docreader）、Redis TLS、SSRF 安全 HTTP 客户端（v0.7.0 全面加固：重定向二次验证、内网地址阻断）。
- **API Key 治理（①）**：v0.7.0 作用域租户 API Key（能力授予 + 限定 KB）+ Principal 模型（API Key 与用户分离为独立主体）；v0.7.1 平台级 API Key（控制面自动化 + 审计查看）；API 集成演练场。
- **身份（①）**：OIDC（`/auth/oidc/start` 端点 v0.8.0，JWKS 验证 ID-token 签名 #2799）、可选密码复杂度策略、v0.8.0 加固自助改密。
- **IM 接入（①）**：源码 `internal/im/` 实证 9 个通道——wecom/feishu/mattermost/qqbot/slack/telegram/wechat/dingtalk/yunzhijia（README 另列 Lark 国际版，共 10 种）；功能：引用回复上下文、线程会话、斜杠命令与问答队列、管理员级会话治理；另有微信小程序、Chrome 扩展、CLI（`cli/`）多客户端。

## 5. 已知短板与风险

1. **安全披露集中（严重）**：2026 年披露 7 个 CVE，均集中于 0.2.x-0.3.x 时代、已在后续版本修复，但反映早期 MCP 面与多租户面攻击面设计缺陷：
   - CVE-2026-22688（MCP stdio 命令注入，CVSS 9.9，修于 0.2.5）
   - CVE-2026-30861（MCP 配置验证绕过致未认证 RCE，CVSS 9.9，修于 0.2.10）
   - CVE-2026-30860（SQL 注入绕过致数据库服务器 RCE，修于 0.2.12）
   - CVE-2026-30856（MCP 工具名模糊约定劫持 + 间接提示注入，修于 0.3.0）
   - CVE-2026-30855（租户管理 IDOR 越权，任意认证用户可接管租户，2026-03-06 披露）
   - CVE-2026-8786（KB 初始化接口授权绕过 kbId 操纵，≤0.3.6，有公开 PoC）
   - CVE-2026-91750（URL 导入 SSRF 重定向二次验证缺失，修于 0.7.0）
   - 启示：**开放注册 + MCP 任意工具 + 多租户**组合是高危面；生产部署必须升级最新版、关公开注册、出口流量过滤（来源：vuldb/opencve/dependabot 等漏洞库）。
2. **英文社区薄弱（③）**：2026 年社区对比表中英文社区评"几乎为零"，教程生态未跨出中文圈（社区集中于微信群/Zhihu）；社区成员自建 weknora-english-guide 填补空白；选型决策中"想要更大英文社区"是选择 RAGFlow 的核心理由之一（dev.to 文章，2026-05）。
3. **复杂 PDF 解析非强项（③④）**：内置 pdf_parser + 可选 MinerU 外部服务的模式，与 RAGFlow 内置深度版面解析器（DeepDoc）定位不同；社区对比定位"不是最偏算法研究/文档解析"的框架。未检索到 WeKnora 官方复杂 PDF 解析基准数据。
4. **中文分词深度有限（①）**：gojieba 仅用于评测分词；BM25 关键词检索依赖向量库引擎自身实现（pgvector 走 PG 全文检索/ParadeDB，ES 走 ES 分析器），跨引擎中文关键词效果一致性需自测。未检索到官方中文 BM25 检索质量基准。
5. **快速迭代的升级成本（④）**：双周级发布 + 大量迁移文件（CHANGELOG 每版含 migration 文件名），生产环境追版本有升级/回归测试负担；v0.8.0 含 Breaking Change（本地沙箱后端移除、Docker 后端默认关闭）。
6. **功能与文档节奏错位（①）**：MCP 工具数 README 称 29、源码实测 33，反映文档更新滞后于代码（双周节奏下的普遍现象）。
7. **单点追踪绑定（②）**：Langfuse 是唯一追踪后端（Jaeger 已移除），不接受其他可观测栈的企业需额外适配。
