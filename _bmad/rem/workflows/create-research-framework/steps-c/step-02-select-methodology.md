# Step 02: 方法论选择与论证
## 目标
根据课题分析结果， 选择最适合的研究方法论，并论证选择理由。
## 输入
- 课题分析报告（Step-01输出）
## 输出
- 方法论选择报告
## 方法论选择矩阵
### 决策逻辑
**优先级：研究问题类型 > 预期成果类型**
```
         预期成果类型
       ┌────────────────────────────────────────┐
       │  新理论  │ 系统模型 │ 设计方案 │
研   ┌────────┼────────┼────────┼────────┤
究   │ 根本性问题 │ ●首选   │ ○次选   │ ○可选   │
问   ├────────┼────────┼────────┼────────┤
题   │ 系统性问题 │ ○次选   │ ●首选   │ ○可选   │
类   ├────────┼────────┼────────┼────────┤
型   │ 实践性问题 │ ○可选   │ ○次选   │ ●首选   │
    └────────┴──────────┴──────────┴────────┘
● = 首选方法论
○ = 可行但非最优
```
### 内置方法论
| 方法论 | ID | 适用场景 | Agent生成策略 |
|--------|-----|---------|---------------|
| **第一性原理** | first-principles | 根本性问题、理论构建 | 预设模板为主 |
| **系统性思维** | systems-thinking | 系统性问题、复杂系统分析 | 预设+动态 |
| **DSR设计科学** | dsr-design-science | 实践性问题、解决方案设计 | 预设+动态 |
## 执行流程
### 1. 读取课题分析结果
从Step-01输出中获取：
- 核心研究问题
- 问题类型
- 预期成果类型
- 涉及领域
### 2. 匹配方法论
根据决策矩阵进行匹配：
```yaml
methodologySelection:
  primaryMatch:
    id: "methodology-id"
    name: "方法论名称"
    confidence: 0.9
    reason: "匹配原因"
  alternatives:
    - id: "alternative-1"
      name: "备选方法论"
      confidence: 0.7
```
### 3. 评估方法论适配性
对每个候选方法论评估：
- 与研究问题的匹配度
- 与预期成果的匹配度
- 与领域特性的匹配度
- 实施复杂度
### 4. 生成选择报告
## 输出模板
```markdown

{date}

## 方法论评估
| 方法论 | 问题匹配度 | 成果匹配度 | 领域匹配度 | 综合评分 |
|--------|-----------|-----------|-----------|---------|
| 第一性原理 | {score} | {score} | {score} | {total} |
| 系统性思维 | {score} | {score} | {score} | {total} |
| DSR设计科学 | {score} | {score} | {score} | {total} |

### 首选：{selectedMethodology}
- **选择理由**：
  1. {reason1}
  2. {reason2}

### 备选方案
如果方法论不适配，可考虑：
- {alternative1}
- {alternative2}

{如果内置方法论都不适配，建议扩展新方法论}
```
