# Step 01: 课题分析与理解
## 目标
深入分析用户输入的研究课题，提取关键信息， 为后续的方法论选择和团队组建提供基础。
## 输入
- 用户输入的研究课题描述
## 输出
- 课题分析报告
## 执行流程
### 1. 课题信息提取
从用户输入中提取以下信息：
```yaml
topicAnalysis:
  # 卟始课题描述
  rawTopic: "用户输入的原始描述"
  # 核心研究问题
  coreQuestion: "识别出的核心研究问题"
  # 研究问题类型
  questionType: "根本性问题/系统性问题/实践性问题"
  # 预期成果类型
  expectedOutput: "新理论/系统模型/设计方案"
  # 涉及领域
  domains:
    - "领域1"
    - "领域2"
  # 关键词
  keywords:
    - "关键词1"
    - "关键词2"
  # 约束条件
  constraints:
    - "约束1"
    - "约束2"
```
### 2. 研究问题类型判断
根据核心研究问题的特征，判断问题类型：
| 问题类型 | 判断依据 |
|---------|--------|
| **根本性问题** | 包含"为什么"、"本质"、"根本原因"等词汇 |
| **系统性问题** | 包含"如何关联"、"整体"、"系统"等词汇 |
| **实践性问题** | 包含"如何解决"、"如何改进"、"如何实现"等词汇 |
### 3. 预期成果类型判断
根据用户描述的预期产出，判断成果类型：
| 成果类型 | 判断依据 |
|---------|--------|
| **新理论/新模型** | 包含"理论"、"模型"、"框架"等词汇 |
| **系统模型/因果图谱** | 包含"系统模型"、"因果图"、"关系图"等词汇 |
| **设计方案/框架/原型** | 包含"方案"、"设计"、"原型"、"解决方案"等词汇 |
### 4. 领域识别
从课题描述中识别涉及的研究领域：
- 自然科学：物理、化学、生物、医学等
- 社会科学：经济、管理、心理学、社会学等
- 工程设计：计算机、机械、电子、建筑等
- 跨学科：涉及多个学科的交叉领域
### 5. 约束条件提取
识别研究约束：
- 时间约束
- 资源约束
- 方法约束
- 伦理约束
- 范围约束
